# T9.1 — Sidebar groups for uncommitted work

**Phase:** 9 · **Size:** M · **Depends on:** T5.2, T5.6, states review (2026-09-18)

Approved design: `docs/mockups/review-sidebar-groups.html` (published 2026-09-18, decisions D1–D9, all
recommendations taken). This file is the implementation spec; where it is more precise than the mockup,
this file wins.

## Why

The sidebar pins a layer chip (`staged` / `unstaged` / `untracked`) to every row. At 220–300 px the chip
wins over the file name, a file in two layers wears two chips, and the sidebar cannot answer "what have I
not staged yet?". VS Code's Source Control view keeps the layer in a group header and leaves the row to a
letter, a name and numbers. We take the grouping and keep everything diffgit already has that VS Code
lacks: `+n −m` per file, viewed ticks, the committed-on-branch layer.

## Model (`src/ui/treeModel.ts`)

```ts
export type SidebarGroupId = "conflict" | "staged" | "unstaged" | "untracked" | "committed";
/** D1: display order. */
export const GROUP_ORDER: readonly SidebarGroupId[] = ["conflict", "staged", "unstaged", "untracked", "committed"];
/** D3: a file appears once, in the least-committed layer it touches. */
export function groupOf(file: Pick<FileDiff, "layers">): SidebarGroupId
//   precedence: conflict → unstaged → staged → untracked → committed
export interface FileGroup { id: SidebarGroupId; files: FileDiff[]; tree: TreeNode[] }
/** Non-empty groups in GROUP_ORDER; `files` keep the engine (path) order; `tree = buildTree(files)`. */
export function groupFiles(files: readonly FileDiff[]): FileGroup[]
export interface LayerCodeInfo { x: string; y: string; label: string }
/** D4: git's `status --short` XY column, or null for a committed-only file. */
export function layerCode(file: Pick<FileDiff, "layers" | "status">): LayerCodeInfo | null
```

`layerCode` rules (letter = `M A D R C T` from `status`; `"·"` is the empty column):

| layers | x | y | label |
|---|---|---|---|
| contains `conflict` | `U` | `U` | `Merge conflict (UU)` |
| contains `untracked` | `?` | `?` | `Untracked file (??)` |
| `staged` and `unstaged`, status ≠ deleted | letter | `M` | `Staged, then edited again (<x><y>)` |
| `staged` and `unstaged`, status = deleted | `M` | `D` | `Staged, then deleted (MD)` |
| `staged` only | letter | `·` | `Staged only (<letter>·)` |
| `unstaged` only | `·` | letter | `Unstaged only (·<letter>)` |
| otherwise (committed only) | — | — | `null` |

Group labels (component side, not the model): `Conflicts`, `Staged`, `Unstaged`, `Untracked`,
`Committed on <compare>` where compare is `diff.source.source` (the display name, e.g. `feature`).

Folder summary helper (pure, in `treeModel.ts`):
```ts
export function dirSummary(node: TreeDir, stats: (f: FileDiff) => FileDiff["stats"]): { files: number; additions: number; deletions: number; complete: boolean }
```
`complete` is false when any countable file inside (not binary, not tooLarge) has no stats yet.

## Store (`src/ui/store.ts`, `src/ui/persistence/prefs.ts`)

- `export type SidebarGroup = "layer" | "path"`; `Prefs.sidebarGroup: SidebarGroup`, default `"layer"`
  (D2). `validatePrefs` accepts only the two literals.
- `selectHasLayers(s: Pick<StoreState, "diff">): boolean` — true when any file has a layer other than
  `committed`. Grouping is possible only then (D2); the second header row and the group headers exist
  only then.
- `selectGroupedModel(s: Pick<StoreState, "diff" | "filter">): FileGroup[]` — memoised on the identity of
  `selectVisibleFiles(s)` exactly like `selectTreeModel`.
- `selectGroupTotals(s: Pick<StoreState, "diff">): Record<SidebarGroupId, number>` — counts over the
  **unfiltered** diff, memoised on `diff.files`; the header shows `k of n` while a filter is active (D5).
- New action `setViewed(ids: string[], viewed: boolean): void` — same persistence and `collapsed` rules
  as `toggleViewed`, one `set()` for the whole batch, one `saveViewed` per file.

## Sidebar (`src/ui/components/Sidebar.tsx`)

- Row 1 (36 px) unchanged: count / `n of m files`, `Tree | Flat`.
- Row 2 (30 px, `border-b border-line`, rendered only when `selectHasLayers`) — D9: left, a mini segmented
  control identical in style to `Tree | Flat` with `Layer | Path` (`aria-pressed`, `fieldset` + sr-only
  legend "Group files"), writing `prefs.sidebarGroup`; right, `text-[11px] text-muted`
  `<n> uncommitted` where n = files with a non-committed layer in the whole diff.

## FileTree (`src/ui/components/FileTree.tsx`)

- `grouped = layout-independent = selectHasLayers && prefs.sidebarGroup === "layer"`.
- `Row` gains `{ key: "g:<id>", kind: "group", group: FileGroup, depth: 0 }`; `estimateSize` 28 px for it.
- Rows when grouped: for each group in order → header row, then (if not collapsed) `flattenTree(group.tree, …)`
  in tree layout or the group's files at depth 0 in flat layout. `fileRows`, `j`/`k`, `v`, `prioritise`
  unchanged (they already skip non-file rows).
- Collapsed dirs are keyed `${group.id}:${path}` when grouped and `path` otherwise, so the same directory
  can be open in Staged and closed in Unstaged. Collapsed groups: `useState<Set<SidebarGroupId>>`.
- **Container role when grouped: always `role="tree"`** (both layouts); headers are
  `role="treeitem" aria-level={1} aria-expanded={open}` with accessible name
  `"<label>, <count> files"` (`aria-label`); rows inside a group get `aria-level={depth + 2}`. Not
  grouped: exactly today's markup (`tree`/`treeitem` in tree layout, `listbox`/`option` in flat).
- **Header anatomy (D6)**, 28 px, `sticky top-0 z-[1] bg-surface-sunken border-b border-line`, padding-left
  10 px, gap 6 px, `select-none`:
  1. chevron `lucide:chevron-down` / `chevron-right` 9 px `text-muted`;
  2. dot 7 px round, `aria-hidden`, background token by layer: `bg-chip-conflict-fg`, `bg-chip-staged-fg`,
     `bg-chip-unstaged-fg`, `bg-chip-untracked-fg`, committed → `bg-muted`;
  3. label `text-xs font-semibold`;
  4. count pill `font-mono text-[10px] leading-[15px] font-semibold px-[5px] rounded-full border border-line
     bg-surface-raised`: `<k>` or `<k> of <n>` while filtering (`n` from `selectGroupTotals`);
  5. spacer (`flex-1`);
  6. `+n −m` (`font-mono text-[11px]`, `text-success` / `text-danger`) summed over the group's visible
     files that have stats; omitted entirely when no file in the group has stats yet;
  7. viewed `k/n` (`font-mono text-[11px] text-muted`); when `k === n` (n > 0): `✓ k/n` in `text-success`
     and the whole header gets `opacity-55`;
  8. actions, `hidden group-hover:inline-flex group-focus-within:inline-flex` (Tailwind `group` on the header):
     two 20 px icon buttons (`hover:bg-line`), `lucide:check-check` "Mark all in <label> viewed"
     (when every file is already viewed: `lucide:rotate-ccw` "Clear viewed in <label>") calling
     `setViewed(ids, !allViewed)`, and `lucide:list-collapse` "Collapse other groups" which collapses every
     other group and opens this one. Both `type="button"`, `aria-label`, `title`, `tabIndex={-1}`,
     `onClick` stops propagation. (Deviation from the mockup, recorded in the CHANGELOG: the mockup's
     "only this group" set a `layer:` filter token, but `layer:staged` also matches a staged-then-edited
     file that lives under Unstaged; collapsing the other groups has no such mismatch.)
  Clicking the header (not a button) toggles the group. Virtualised mode (> 300 rows) positions rows with
  transforms, so headers cannot be sticky there; acceptable, note it in the CHANGELOG.
- **Keyboard on a header** (P5): `Enter`/`Space` toggle; `ArrowRight` expands, or moves to the next row
  when already open; `ArrowLeft` collapses when open, otherwise nothing; `v` calls
  `setViewed(ids, !allViewed)` and `preventDefault()` so the global `v` does not also fire. `ArrowLeft` on
  a depth-0 row inside a group focuses the group header. `Home`/`End`/`ArrowUp`/`ArrowDown` unchanged.
- **Folder rows (D7)**: while collapsed, after the name: `font-mono text-[11px] text-muted` file count and
  `+n −m` (`dirSummary`; the numbers are omitted while `complete` is false, the count always shows). While
  open: nothing, exactly today.
- **File rows**: pass `code` (see FileRow) — grouped: `layerCode(file)` only when the file has both
  `staged` and `unstaged`; path mode: `layerCode(file)` whenever non-null.
