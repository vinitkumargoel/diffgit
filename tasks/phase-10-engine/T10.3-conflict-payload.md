# T10.3 — Conflict payload (three-way from index stages)

**Size:** M · **Depends on:** T10.2 · Atlas tab 06

## Deliverables
- `src/engine/api.ts`: `ConflictPayload { id; generation; base: SideBlob | null; ours: SideBlob | null;
  theirs: SideBlob | null; oursHunks: HunkModel | null; theirsHunks: HunkModel | null;
  worktree: { text: string; markers: { start: number; end: number; oursEnd: number; baseEnd?: number }[] } | null;
  resolvedInWorktree: boolean; kind: "both-modified" | "both-added" | "deleted-by-us" | "deleted-by-them" | "both-deleted";
  labels: { ours: string; theirs: string } }` with
  `SideBlob { oid: Oid; text: string | null; size: number; binary: boolean }`.
- `src/engine/diff/conflict.ts` (new): build the payload from `IndexSnapshot.conflicts[path]` stages
  (1 = base, 2 = ours, 3 = theirs), `readBlob`, `computeHunks(base→side)` with the existing
  `TextDiffOptions`; parse conflict markers (`<<<<<<<`, `|||||||`, `=======`, `>>>>>>>`) in the
  working-tree file (`diff3` style supported); `resolvedInWorktree` = file exists and has no markers.
  Labels: ours = `HEAD`/branch name, theirs = from `RepoOperation` (`onto` commit or `MERGE_HEAD`
  display). Size gates: sides over 1 MB return `text: null` (UI gates), binary → `text: null`.
- `EngineApi.conflict(generation, id)`; `STALE` and `CANCELLED` semantics as `fileDiff`.
- `FileDiff` for a conflict row: `layers` includes `conflict` (exists), `status` per kind
  (`both-added` → added, `deleted-by-*` → deleted, else modified).

## Tests
- `rebase-conflict` and `merge-conflict`: stage oids equal `git ls-files -u`; marker ranges equal the
  line numbers of the markers in the checked-out file; `resolvedInWorktree` flips after the test edits a
  copy of the fixture (use the memory handle to overlay); modify/delete yields `deleted-by-them` with
  `theirs: null`.

## Acceptance
- [ ] Payload parity with `git ls-files -u` on both fixtures; `bun run check` green.
