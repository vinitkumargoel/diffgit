# T10.12 — Submodules, worktrees, LFS, jj, patch parsing

**Size:** M · **Depends on:** T10.11 · Atlas tabs 19, 17

## Deliverables
- `src/engine/git/submodules.ts`: parse `.gitmodules`; for each gitlink at HEAD: `recorded` oid,
  `checkedOut` from `<path>/.git` (file with `gitdir:` → read that HEAD, or directory), `dirty` null
  (not computed). `listSubmodules()`.
- `src/engine/git/worktrees.ts`: `.git/worktrees/*/{HEAD,gitdir}` → `WorktreeInfo[]` plus the main
  checkout as `isThis: true`; `prunable` when `gitdir` target cannot be read (best effort; FSA cannot
  see outside the picked folder, so a missing sibling path is reported as `path: null`).
- LFS: `FileClassification.lfs?: { oid: string; size: number }` parsed from pointer text
  (`version https://git-lfs.github.com/spec/v1`) on either side in `describeFile`.
- `RepoInfo.jj` already set (T10.2); when true, a detached HEAD is not reported as `detached` in
  `headDisplay` but as `jj working copy @ <sha7>` and no info banner about detachment is emitted.
- `src/engine/diff/parsePatch.ts`: unified diff (git and plain) → `{ files: FileDiff[]; hunks: Record<id, HunkModel>; stats }`;
  supports rename/mode/binary headers; malformed → `NOT_A_PATCH`. `parsePatch(text)` on `EngineApi`
  works without an open repository (a `PatchSession` in `worker.ts`) — see Design §14.6 "patch-only".
- `EngineApi.listSubmodules`, `listWorktrees`, `parsePatch`.

## Tests
- `submodule` fixture: recorded vs checked-out oid; `worktree` fixture (main + linked): two entries;
  LFS pointer text from a crafted blob parses; jj: a fixture with an empty `.jj/` directory and a
  detached HEAD reports `jj: true`; `parsePatch` round-trips `patchText` output of `basic` and
  `renames` (same file set, statuses and hunk line counts) and rejects garbage.
