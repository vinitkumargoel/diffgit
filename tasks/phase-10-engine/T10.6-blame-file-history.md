# T10.6 — Path history with rename follow, and blame

**Size:** L · **Depends on:** T10.5 · Atlas tab 02

## Deliverables
- `src/engine/git/pathHistory.ts` (new): `pathHistory(ref, path, {follow, limit, cursor})` — walk
  first-parent from `ref`, keep commits where the blob id at `path` differs from the parent; when the
  path is absent in the parent and `follow`, run `detectRenames` between parent and commit trees
  restricted to candidates (deleted-in-parent/added-in-commit) and continue on the old path
  (`renamedFrom`); `whitespaceOnly` via `computeStats` with `ignoreWhitespace` = 0 changes; `status`.
- `src/engine/diff/blame.ts` (new): `blame(ref, path, opts)` — start from the newest content
  (worktree when `includeWorktree` and the file is dirty: those lines get `oid: null`), iterate the
  path history newest → oldest, `lineDiff` between consecutive revisions, attribute unchanged lines to
  the older side, bitset of unassigned lines for early termination, `maxRevisions` cap
  (`BLAME_CAPPED`, remaining lines attributed to the oldest revision seen), `ignoreWhitespace` skips
  whitespace-only revisions. Output `BlamePayload` with `origLine`/`origPath` (renames followed).
- Progress `"blame"` with `done/total` per revision; abortable; one in flight.
- `EngineApi.pathHistory`, `EngineApi.blame`.

## Tests
- `history` fixture: `pathHistory` equals `git log --follow --format=%H -- <renamed file>` and without
  `--follow`; `whitespaceOnly` true for the indent commit; `blame` equals `git blame --porcelain`
  (commit oid per line, original line number) for three files including the renamed one, with and
  without `-w` (expectations from T10.0); worktree edit attributes to `null`; `maxRevisions: 2` yields
  `capped: true` and still covers every line.
