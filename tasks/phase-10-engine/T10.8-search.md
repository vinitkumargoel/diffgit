# T10.8 — Search: commits, working tree, scoped pickaxe

**Size:** M · **Depends on:** T10.7 · Atlas tab 05

## Deliverables
- `src/engine/search/commits.ts`: substring (case-insensitive) or regex over subject+body, author
  name/email, SHA prefix, over the commits walked so far (T10.5 cache) or a fresh capped walk; `limit`.
- `src/engine/search/worktree.ts`: grep over tracked + untracked text files (ignore rules applied,
  `generated` skipped, files > 1 MB skipped), literal by default, regex opt-in with a 200-char cap and a
  50 ms per-file budget (abort the file, count it as skipped), streamed via the existing stats
  concurrency limiter, `SearchHit{kind:"file", path, line, text}` (text trimmed to 200 chars),
  `limit`, `SEARCH_CAPPED`.
- `src/engine/search/pickaxe.ts`: for the last `commits` commits from `HEAD` (first-parent), tree-diff
  vs parent restricted to `path` prefix, count occurrences of `query` on each side of changed text
  blobs, report commits where the count changes (`delta`), plus the working tree as `oid: undefined`
  hit when it changes the count. Mandatory `commits` (default 200 from the UI) and optional `path`.
- `EngineApi.search`; progress `"search"` with `done/total`; abortable; one in flight.

## Tests
- `history`: commit search finds by subject, author, email and SHA prefix; worktree grep on `basic`
  matches `grep -rn` output for a literal (recorded); pickaxe equals `git log -S<q> --format=%H -n 200`
  on `history` for two strings; regex timeout test with a catastrophic pattern completes under 1 s.
