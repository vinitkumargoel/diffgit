# T10.5b — Walker review fixes

**Size:** M · **Depends on:** T10.5, T10.6 · Source: independent review of commit 59d121a (2026-09-19)

Fix, in this order, with a regression test per item (fixtures built by the real git CLI in
`scripts/make-fixtures.sh`, expectations from git):

## Blocker
- **B1** Tags pointing at non-commits (a lightweight tag on a blob — git.git ships `refs/tags/junio-gpg-pub`)
  crash `walkCommits({all})`, `markReachable` and `reflog` with an isomorphic-git `ObjectTypeError`
  (`session.ts` seeds from `listTags` targetOid; `walk.ts` `nodeOf`/`reachableFrom` call `readCommit`).
  Fix: peel/type-check seeds (skip non-commit targets exactly like `git log --all`); make
  `CommitReader.meta` return null for non-commits and skip them. Fixture: `tags` gains a blob tag and a
  tree tag; parity test against `git log --all --format=%H`.

## Should fix
- **S1** Streaming indegree emits a parent before a later-discovered child under committer-date skew and
  then leaks a lane (`placeCommit` reserves a lane for an already-emitted oid). Fix: collect the page's
  candidate window (`limit` + slack) before topological release the way git does, or at minimum never
  reserve a lane for an emitted oid and never emit a dangling edge. Fixture: `skew` built with
  `GIT_COMMITTER_DATE` decreasing toward the parents (commit-tree with explicit dates); parity with
  `git log --date-order`; the `assertContinuous` structural invariant must hold. Update the contracts
  paragraph that claims agreement with git in every case to state the actual guarantee.
- **S2** A cursor whose request key no longer matches silently restarts from page 1 → duplicated rows /
  infinite first page while refs move. Fix: throw `STALE` on key mismatch (malformed cursor → `INTERNAL`
  with detail); document in `docs/v2-contracts.md` that the UI must restart the list on `STALE`.
- **S3** `aheadBehind` returns arbitrary numbers once the 10,000 cap bites (two independently truncated
  sets). Fix: git's algorithm — one date-ordered queue seeded LEFT/RIGHT, paint COMMON, stop when nothing
  interesting remains (`still_interesting`); memoise reachability per `(a,b)` pair per refs generation
  so `branchCells` does not re-walk per row. Test: criss-cross + a 30-commit trunk with the cap scaled
  down through an option, expecting exact counts.
- **S4** Cursor is O(commits walked) (~47 B/commit; ~2.3 MB at the cap, ~1 GB cumulative transfer).
  Fix: keep walk state in the session keyed by an opaque token (the session single-flights the method);
  the cursor is the token; on worker restart a stale token → `STALE` (UI restarts).
- **S5** No `AbortSignal` is ever wired: `single()` only rejects after the superseded call completes.
  Fix: an `AbortController` per single-flight method, abort the previous controller on a new call, thread
  `signal` into `WalkDeps`, `reachableFrom`, `CommitStatsDeps`, and check it in the loops; progress
  `"history"` reported per 500 commits, not once at the end.

## Nits to take
- Run `git commit-graph write --reachable` on the `octopus` fixture so the EDGE chunk path is executed by
  the suite (nit 1).
- `upstreamOf`: resolve through the remote's fetch refspec and fall back to a `refs/remotes/<remote>/<short>`
  lookup by fullName; `branch.<n>.merge` outside `refs/heads/` must not produce `origin/refs/for/x` (nit 3).
- Enforce `MAX_LANES` in `placeCommit` (fold overflow into the last lane, `laneCount` capped) and expose
  `WalkPage.laneOverflow: boolean` so the UI can suggest first-parent (nit 4; add to contracts).
- Input hardening: `limit` NaN/≤0 → `INTERNAL`; dedupe seeds; validate every cursor field (nit 5).
- `Set`-based dedup for seeds/tips (nit 6). Committer date for `BranchRow.lastCommit.timestamp` (nit 7).
- `commitGraph.position`: clamp fanout lo/hi to `count` (nit 9).
- Replace the vacuous perf-5k first-page number with a fixture of ≥ 200 commits (`FIXTURES_PERF=1`
  builds `perf-log`: 2,000 linear commits + 50 branches) and record the real first-page time in
  `docs/perf.md` (nit 8).
- The three `catch` sites that swallow I/O errors (`branches.ts lastCommitOf`, `commitGraph.ts load`,
  `commits.ts stats`) must emit a `RepoWarning` (`IO_ERROR` detail) instead of staying silent (nit 2).
