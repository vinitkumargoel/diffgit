# T10.11 — Bisect step and rebase preflight

**Size:** M · **Depends on:** T10.10 · Atlas tabs 15, 16

## Deliverables
- `src/engine/git/bisect.ts`: `bisectStep({good, bad, skipped})` — candidates = reachable from `bad`
  minus reachable from any `good` (walk with the T10.5 graph), minus `skipped`; midpoint = candidate
  whose ancestor count within the candidate set is closest to half (git's weighting); `remaining`,
  `steps = ceil(log2(remaining))`, `firstBad` when exactly one candidate remains (or zero → `bad`).
- `src/engine/git/preflight.ts`: `rebasePreflight(branchRef, ontoRef)` — merge base; `rows` = commits
  of branch since the merge base (oldest first), each with changed paths vs parent (tree diff), `merge`
  (two parents), `signed`; `ontoAdvanced` = commits on onto since the merge base; for each row path,
  if any onto-side commit changed the same path (renames mapped through `detectRenames` on the two
  tips): compare hunk line ranges (from `computeHunks` of each side vs the merge base) — overlapping or
  adjacent (≤ 1 line apart) ranges → `likely`, same file disjoint → `possible`; row prediction = worst
  of its overlaps; `command` = `git rebase -i <onto>` or `git rebase -i --rebase-merges <onto>` when
  any row is a merge; `todo` = `pick <sha7> <subject>` lines.
- `EngineApi.bisectStep`, `EngineApi.rebasePreflight`.

## Tests
- `history`: bisect over a linear range picks the same midpoint sequence as `git bisect` replayed via
  `git rev-list --bisect` at each step (record with T10.0 or compute in-test when git is available);
  preflight on a crafted pair of branches in the `history` fixture (add them in `make-fixtures.sh`:
  one commit that will conflict, one that touches the same file elsewhere, one clean) yields
  `likely`, `possible`, `clean` and the actual `git rebase` outcome recorded by the fixture script
  confirms the `likely` one conflicts.
