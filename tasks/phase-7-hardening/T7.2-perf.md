# T7.2 — Performance pass

**Phase:** 7 · **Size:** M · **Depends on:** T7.1 · **Blocks:** T7.5
**Plan refs:** §9 perf budgets, §6.7, §11 R3

## Budgets (laptop, Chrome, `perf-5k` fixture with ~30 MB packed objects)
| Metric | Budget |
|--------|--------|
| Open → file list visible | < 3 s |
| Recompute after single file edit | < 500 ms |
| Sidebar stats fully populated (5k files) | < 4 s, progressive |
| 3000-line diff render | < 500 ms |
| Idle CPU (polling mode) | < 3 % |
| Main-thread long tasks during compute | none > 50 ms |

## Deliverables
- `scripts/perf.ts` (bun) timing engine phases on `perf-5k` and asserting the structural budgets (message counts, payload sizes). Browser budgets are measured **manually** once with `performance.mark` output shown in the hidden `/#debug` panel and recorded in `docs/perf.md`; there is no Playwright perf spec (E2E policy).
- Profiling notes and fixes: batch sizes for stats, `flattenTree` strategy, handle-cache sizing, comlink message sizes (avoid sending full `DiffResult` on every recompute if unchanged — send a diff of ids or a version stamp), Shiki grammar lazy-loading, virtualiser overscan.
- Memory guard (R3): track approximate bytes held by pack cache (isomorphic-git `cache` object size estimation via a wrapper) and warn at 300 MB; expose in a hidden `/#debug` panel with timings.

## Acceptance criteria
- [ ] All budgets met locally and recorded in `docs/perf.md`. **CI enforces structural budgets only via `scripts/perf.ts` in bun** (≤ N worker messages per recompute, `DiffResult` payload ≤ X kB for 5k files, handle-cache evictions per refresh ≤ paths reported); absolute timings run only with `PERF_STRICT=1` on a developer machine because GitHub runner timings are noise.
