# T5.0 — Spike S1: choose the diff renderer

**Phase:** 5 · **Size:** S · **Depends on:** T0.1 · **Blocks:** T5.3
**Plan refs:** §11 S1, §1 finding 5, §7 · **Design refs:** Design.md §3.2, §3.5, §7.6

## Goal
Decide, with evidence, between `@git-diff-view/react` and `react-diff-view` (+ our `HunkModel`) for the file diff body.

## Deliverables
- `spikes/s1-diff-renderer/` (kept in repo, excluded from build): two Vite pages rendering the same three cases: (1) 200-line TS file with 6 hunks, (2) 3000-line file, (3) rename with 60% similarity.
- `docs/adr-001-diff-renderer.md` with the decision and a comparison table.

## Must verify for `@git-diff-view/react`
- Diff from two strings via `generateDiffFile` (or `DiffFile.createInstance`), split + unified toggle, Shiki highlighting with **bundled** grammars (no network; check no fetch in DevTools with the T0.2 CSP applied in preview), word-level diff, **expand context** ("expand up/down/all" at hunk boundaries — unconfirmed in README), whitespace-ignore (or we pre-filter via our hunk model), running the diff computation in a Web Worker (`@git-diff-view/core` in worker, serialise, hydrate on main).
- Bundle size added (gzip), render time for case (2), memory.
- Theming hooks for GitHub light/dark colours.

## Must verify for `react-diff-view`
- Rendering from our `HunkModel` (T3.4) converted to its `hunks` shape, expand context via `expandFromRawCode`-style helper (we have full old/new text), tokenisation with `refractor` for highlighting, split/unified, word diff via `markEdits`.
- Same measurements.

## Decision rule
Prefer `@git-diff-view/react` if expand-context and worker mode work and the bundle is < 250 kB gzip added. Otherwise `react-diff-view`.

## Acceptance criteria
- [ ] ADR written with numbers; T5.3 task file updated with the chosen library's API notes (edit `T5.3-diff-pane-file-card.md` "Renderer" section).

## Amendments (review round 1)
- **CSP is an input to the decision.** Run every spike page under `vite preview` (which now serves the production headers, T0.1). Shiki's default loader fetches `onig.wasm`, which `connect-src 'none'` blocks: evaluate `@shikijs/engine-javascript` (regex engine, no WASM) first; fall back to the inlined WASM import (`shiki/wasm` bundled as base64) only if the JS engine misses needed grammars. Record bundle deltas for both.
- Record the ADR decision **with the CSP result** for each candidate; a renderer that needs network is disqualified.

## Design amendments (approved direction A, 2026-09-16)
- Each spike page is styled to Design §7.6 (fixed-layout table, 46/46/22 px unified gutters, 12 px / 20 px monospace, hunk header with `↑ ↓ all` mini-buttons) using the §3.2 diff tokens, so the ADR compares how close each renderer can get to the spec, not its default look.
- Highlighting uses Shiki `github-light` / `github-dark` (Design §3.5); note in the ADR whether the renderer lets us map its theme from CSS variables (Design §11, last bullet).
- The comparison table gains a row "Can match Design §7.6 without forking the renderer's CSS" (yes / with overrides / no).
