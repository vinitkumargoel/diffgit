# T5.3 — DiffPane + FileCard (the diff body)

**Phase:** 5 · **Size:** L · **Depends on:** T5.0, T4.2 · **Blocks:** T5.4
**Plan refs:** §6.1 (main column), §6.4 styling, §6.7, ADR-001 · **Design refs:** Design.md §3.2, §5, §6, §7.5, §7.6, §8

## Goal
The GitHub "Files changed" body: virtualised list of file cards, each with sticky header and a rendered diff, lazy-loaded per file.

## Deliverables
- `DiffPane.tsx`: virtualised (`@tanstack/react-virtual`, dynamic measurement) over `visibleFiles`; each card mounts its diff only when within ±1 viewport (`loadFileDiff(id)` on approach); scroll-to-file API used by Sidebar; preserves scroll position on recompute where the file still exists.
- `FileCard.tsx`: sticky header with: collapse chevron, status icon, path (renames `old → new (87%)`), mode change text (`100644 → 100755`), `+n −m`, "Viewed" checkbox (collapses the card when checked, like GitHub), copy-path button, expand-all-context button, per-file unified/split override menu (optional).
- `DiffBody.tsx`: renders with the library chosen in ADR-001 (see **Renderer** below). Shows word-level highlights, line numbers both sides, hunk headers `@@ -a,b +c,d @@` with expand-up/down/all controls, whitespace-ignore honoured (re-request `fileDiff` with the flag; cache both variants), syntax highlighting by `language` with bundled grammars loaded lazily per language chunk.
- `LoadingSkeleton.tsx` for card body; error state per card with retry.
- Colours/tokens per Plan §6.4 in `index.css` as CSS variables for light/dark.

## Renderer
Decided by T5.0 → `docs/adr-001-diff-renderer.md`: **`react-diff-view` 3.3.3 rendering our `HunkModel`**, Shiki 4 (JS regex engine) in a UI-owned worker for syntax colours, `markEdits` for word-level marks. `@git-diff-view/react` was rejected (341.6 kB gzip added, needs patch text + full contents on main, Tailwind-utility markup fights Design §7.6).

API notes (all verified in `spikes/s1-diff-renderer/rdv.tsx`):
- Imports: `import { Diff, Hunk, Decoration, expandFromRawCode, getCollapsedLinesCountBetween, markEdits, tokenize, type HunkData, type ViewType, type TokenNode } from "react-diff-view"`. Do **not** import `react-diff-view/style/index.css`; `src/index.css` styles `.diff` (`table-layout: fixed; width: 100%`), `.diff-gutter` (46 px, `--diff-ctx-num` / `--diff-add-num` / `--diff-del-num`), `.diff-code` (22 px sign column via `::before`, `--diff-add-bg` / `--diff-del-bg`), `.diff-code-edit` (`--diff-add-word` / `--diff-del-word`), `.diff-hunk-header` (`--diff-hunk-bg` / `--diff-hunk-ink`), split gutters 44 px. Starting point: `spikes/s1-diff-renderer/spike.css` (`.rdv` block).
- `HunkModel` → `HunkData[]`: per hunk `{ content: "@@ -a,b +c,d @@", oldStart, oldLines: oldCount, newStart, newLines: newCount, changes }`; per line `ctx` → `{ type: "normal", isNormal: true, oldLineNumber: old, newLineNumber: new, content: text }`, `add` → `{ type: "insert", isInsert: true, lineNumber: new, content }`, `del` → `{ type: "delete", isDelete: true, lineNumber: old, content }`. Put it in `src/ui/diff/toHunkData.ts` with a unit test against `basic.diffresult.json` payloads.
- Render: `<Diff viewType={prefs.viewMode} diffType={"modify"|"add"|"delete"|"rename"} hunks={hunks} tokens={tokens}>{hs => hs.flatMap((h, i) => [<Decoration key=…><HunkHeader …/></Decoration>, <Hunk key={h.content} hunk={h}/>])}</Diff>`. `HunkHeader` is our component (Design §7.6: `@@ -a,b +c,d @@` text + `↑ ↓ all` mini-buttons); the gap above a hunk is `getCollapsedLinesCountBetween(prev, h)` (or `h.oldStart - 1` for the first); the trailing gap is `oldText.split("\n").length - (last.oldStart + last.oldLines) + 1`.
- Expand: `setHunks(expandFromRawCode(hunks, payload.oldText, start, end))` — **old-side** 1-based line numbers, `end` exclusive; "↑" expands `[prev end, h.oldStart)` clipped to 20 lines, "↓" the 20 lines after the hunk, "all" every gap including head and tail (`expandAll()` in the spike). `oldText` is `FileDiffPayload.oldText` (null for added files → nothing to expand above/below except via `newText`; treat added/deleted files as fully shown).
- Word-level: `tokenize(hunks, { highlight: false, enhancers: [markEdits(hunks, { type: "block" })] })` → `tokens` prop. Pure data, so it runs in the highlight worker together with Shiki.
- Syntax colours: `src/ui/highlight/highlight.worker.ts` creates one `createHighlighterCore({ themes: [import("@shikijs/themes/github-light"), import("@shikijs/themes/github-dark")], langs: [], engine: createJavaScriptRegexEngine({ forgiving: true }) })`, loads grammars on demand with `highlighter.loadLanguage(import("@shikijs/langs/<id>"))` (`FileDiffPayload.language`, unknown → plain), and returns react-diff-view tokens: implement `highlight(code, lang)` for `tokenize`'s `refractor` option from `highlighter.codeToHast(code, { lang, theme })` (take `pre > code` children; Shiki emits one `span.line` per line separated by `"\n"` text nodes) — or map `codeToTokensBase` lines to `TokenNode[]` directly. Measured cost: 55 kB gzip core+engine+themes, 16 kB per grammar chunk, 245 ms to tokenise 252 lines of TS on first call — never on the main thread, skip for `tooLarge` files, cache per `${id}|${ignoreWhitespace}|${theme}`.
- Theme: Shiki output carries inline colours for the active theme; re-request tokens on theme change (cheap after the first call) or use Shiki's dual-theme CSS-variable mode (`codeToHast` with `themes: { light, dark }, defaultColor: false`) so `.dark` switches without re-tokenising — prefer the latter (Design §11: theme from CSS variables).
- Performance reference (Chromium 153, production build): 252-line/6-hunk card renders in 54 ms, a 3,000-line file with 2,800 changed lines (5,607 rows) in 414 ms, unified→split for ≈ 5,700 rows in 905 ms. Keep the < 500 ms AC by virtualising cards (T5.3) and gating `tooLarge` (T3.4).

## Acceptance criteria
- [ ] Green; recorded `large`-style 3000-line diff renders < 500 ms after data arrival (measured in dev tools, noted).
- [ ] No network requests during rendering with CSP from T0.2 in `vite preview`.

## Amendments (review round 1)
- **Per-card React error boundary**: a renderer crash on one file shows "Couldn't render this diff [Retry] [View raw]" and never unmounts the pane.
- **Whitespace-only body**: when `whitespaceOnly` (T3.4) and the whitespace toggle is on, render "Whitespace changes only" with a link to show them.
- `generated = true` cards start collapsed with "Generated file, click to expand" (GitHub behaviour).
- Every `fileDiff` request carries `diff.generation`; responses for another generation are discarded.
- Requests for cards scrolled out of view before completion are cancelled via `AbortController` mapped to the worker's per-call cancel (`cancelFileDiff(id)` in T3.5 amendments — add it).
- AC "No network requests" is verified under `vite preview` (production headers).

## Design amendments (approved direction A, 2026-09-16)
- `DiffPane`: 16 px padding, 16 px gap between cards, cards full pane width, pane is the only vertical scroller (Design §6).
- `FileCard` container and sticky `FileHeader` exactly per Design §7.5 (order: chevron, `StatusIcon`, path with dimmed directory, rename `old → new (87%)`, mode change, `+n −m`, chips, then copy / Expand all / Viewed on the right). Header background `--surface-raised`.
- `DiffBody` styled to Design §7.6 regardless of renderer: fixed-layout table, 46/46/22 px unified gutters (44/22 per side in split), 12 px / 20 px monospace, `--diff-*` tokens for rows, gutters, word highlights and hunk headers; hunk header carries the `↑ ↓ all` mini-buttons. Renderer theme is mapped from the CSS variables (Design §11), never hard-coded twice.
- Generated-file collapsed notice, error-boundary body and `LoadingSkeleton` per Design §7.5; Viewed collapse per Design §8.
- Card collapse transition 120 ms, removed under `prefers-reduced-motion` (Design §8).
- AC added: no literal colours in `src/ui/components/{DiffPane,FileCard,FileHeader,DiffBody,LoadingSkeleton}.tsx`; light and dark screenshots of the recorded `large` fixture attached to the CHANGELOG entry (manual, not a test baseline).
