# T6.0 — Spike S3: FileSystemObserver behaviour on a git repo

**Phase:** 6 · **Size:** S · **Depends on:** T0.3 · **Blocks:** T6.2
**Plan refs:** §11 S3, §5.7, §1 finding 4

## Goal
Learn exactly what events Chrome's `FileSystemObserver` emits when git and editors touch a repo, so the classifier in T6.2 is built on evidence.

## Deliverables
- `spikes/s3-observer/index.html` (opened via `vite preview`): pick a folder, `observer.observe(handle, { recursive: true })`, log `records[].type`, `relativePathComponents`, `changedHandle.kind`, timestamps.
- `docs/engine-notes.md` section "S3 results": event sequences for each scenario below, Chrome version, whether events under `.git/objects` are emitted, event count and burst duration.

## Scenarios (run on a copy of `fixtures/worktree`)
1. Save a tracked file in VS Code (atomic-save: write temp + rename) and with `echo >>` (in-place).
2. `git add file`, `git commit`, `git checkout other-branch`, `git switch -` (index.lock create → rename; refs update; packed-refs).
3. `git fetch` from the local bare remote (objects/pack + remote refs).
4. Create/delete an untracked file; create a new directory with files.
5. `git gc` (mass object churn — must not trigger recompute storms).
6. Delete the folder while observing (expect `disappeared`/`errored` record).

## Acceptance criteria
- [ ] All six scenarios logged with sequences.
- [ ] Recommended debounce window and the path classifier rules written as a table for T6.2.
- [ ] Record whether `observe()` on a handle opened with `mode: "read"` works (expected yes).
