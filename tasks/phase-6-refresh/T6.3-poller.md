# T6.3 — Polling fallback

**Phase:** 6 · **Size:** M · **Depends on:** T6.1 · **Blocks:** T7.1
**Plan refs:** §5.7 polling mode

## Deliverables
- `src/ui/refresh/poller.ts`: `startPoller(client, scheduler, opts): () => void`. Runs when the observer is unavailable or failed.
- Engine support: `probe(tier)` is defined and implemented in T3.5 (amendments); this task only consumes it.
- **Tiered intervals** (a per-entry stat sweep is two IPC round-trips per file; 5k entries take 1–2 s, not 300 ms): `git` tier every 3 s; `index` tier every 10 s, adaptive up to 30 s when the last sweep took > 500 ms; `untracked` tier every 30 s. All tiers ×3 when `document.hidden`. Pause while a compute runs; immediate `git` probe on return to visible.
- On signature change → `scheduler.request("poll:git" | "poll:worktree")`.

## Tests
vitest with fake timers and a mock `probe`: interval switching with visibility, change detection triggers the right reason, no probe while busy. Engine-side probe tests live in T3.5.

## Acceptance criteria
- [ ] Green; CPU idle overhead on a 5k-file repo < 3 % averaged over one minute (note in CHANGELOG); the `index` tier back-off is observed to kick in on `perf-5k`.
