# T11.10 — Export menu and review snapshot

**Size:** M · **Depends on:** T11.9, T10.10 · Design §14.6 · Atlas tab 12

## Deliverables
- `ExportMenu` (StatsRow icon button, key `e`): `Copy as unified diff`, `Save as .patch`, `Save review
  snapshot (.html)`, `Copy file list as Markdown`, `Copy stats line`; sizes computed before enabling;
  secret gate: when `secrets.length > 0` the destructive items are replaced by a warning row listing
  files and an `Export anyway` link. Saves use `showSaveFilePicker` when present (suggested name
  `<repo> · <from>…<to> · <date>.<ext>`), else an `<a download>`; never a handle inside the repository
  (assert in tests that no `getFileHandle(..., {create:true})` path exists — the D16 guard already
  greps for it).
- Snapshot: `src/snapshot/` a second Vite entry (`snapshot.html`) that renders `DiffResult` +
  `FileDiffPayload`s + pre-highlighted Shiki HTML from an inlined JSON blob, with the same tokens,
  unified/split, file tree, viewed ticks in `localStorage`, theme toggle, no worker, no network; the
  export builds it by fetching the built snapshot bundle from `/snapshot.js` (same-origin, allowed by
  `connect-src 'self'`? No — `connect-src 'none'`: instead the bundle is imported at build time as a
  string via Vite `?raw` and inlined). Sizes shown in the menu.
- Wire `Export as .patch` in CommitCard and the FileHeader menu (per-file or per-commit patch via
  `patchText(generation, ids)`).

## Tests
- Menu items, sizes, secret gate, clipboard calls with masked content, save path picks the picker
  when available; snapshot renderer test renders a recorded payload (vitest, happy-dom) with tree and
  cards; `scripts/check-dist.sh` extended to assert `snapshot.js` has no `fetch(`/`XMLHttpRequest`.
