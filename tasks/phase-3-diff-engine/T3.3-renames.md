# T3.3 — Rename detection

**Phase:** 3 · **Size:** M · **Depends on:** T3.2, T2.2 · **Blocks:** T3.5
**Plan refs:** §5.6 step 6

## Goal
Pair deleted and added files into `renamed` entries the way `git diff -M` does, within bounded cost.

## Deliverables
- `src/engine/diff/renames.ts`: `detectRenames(files: FileDiff[], load: (side) => Promise<Uint8Array>, opts: { threshold?: 50; limit?: 1000; signal? }): Promise<FileDiff[]>`.

## Algorithm
1. Candidates: `D = files where status=deleted`, `A = files where status=added` (including untracked). Skip when `|D| === 0 || |A| === 0`.
2. **Exact pass**: hash both sides (added worktree files need `hashBlob` of their bytes; tree/index sides have oids). Group by oid; pair by identical oid, preferring same basename, then shortest path distance. Similarity 100.
3. **Similarity pass** on remaining pairs if `|D|×|A| ≤ limit` (from `diff.renameLimit` config if set, else 1000); otherwise add warning `RENAME_LIMIT` and skip.
   - Skip pairs where either side is binary (T3.4's detector, or NUL check inline) or sizes differ by > 4×.
   - Score = `100 * (1 - changedLines / max(oldLines, newLines))` using jsdiff `diffLines` on decoded UTF-8. Greedy best-match: sort pairs by score desc, take pairs ≥ threshold whose endpoints are unused.
4. Merge into one `FileDiff`: `status: "renamed"`, `oldPath`, `newPath`, `similarity`, `layers` = union, `id = newPath`. Keep `modified` semantics for hunks (content still differs unless 100).

## Tests
`renames` fixture parity with `name-status-3dot.json`: exact rename R100, the ~60% rename R with similarity within ±5 of git's, the below-threshold pair stays D+A, the identical-content pair in different dirs → R100. `basic` unchanged. Limit test with synthetic 40×40 candidates and `limit: 100` → warning and no similarity renames.

## Acceptance criteria
- [ ] Parity green; runs < 200 ms on the `renames` fixture.

## Amendments (review round 1) — replaces the limit rule and the scoring
- **Limit rule is git's**: similarity pass runs when `renameLimit² >= |D| × |A|` (default `renameLimit = 1000`, or `diff.renameLimit` from config). The previous `|D|×|A| ≤ limit` was 1000× too strict.
- **Scoring is git's spanhash** (`diffcore-delta.c`): split each side into chunks at `\n` boundaries with a 64-byte cap, hash each chunk (FNV-1a 32-bit is fine; git uses its own), count occurrences per side; `sharedBytes = Σ min(countA, countB) × chunkLen`; `score = sharedBytes * 100 / max(sizeA, sizeB)` computed on **bytes**, so binary files can participate as git does. Drop the jsdiff line-based score. Keep the 4× size pre-filter (git applies an equivalent bound). Git has no per-file size cap; we add `opts.maxSideBytes` (default 8 MB) and warn `RENAME_LIMIT` when a pair is skipped for size.
- Exact pass uses oids from the scan/tree (untracked > 1 MB without oid are hashed here lazily).
- Test tolerance stays ±5 but is expected to be exact for the fixture pairs; note any deviation in CHANGELOG.
