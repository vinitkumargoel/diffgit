# T2.1 — IndexReader: own `.git/index` parser (v2/v3/v4)

**Phase:** 2 · **Size:** L · **Depends on:** T1.1 · **Blocks:** T2.4
**Plan refs:** §5.4, §1 finding 2 (why we do not use isomorphic-git's parser)

## Goal
Parse the git index into an in-memory snapshot, supporting formats 2, 3 and 4, conflict stages, and the extensions that change semantics (`link`, `sdir`). Read-only, checksum-verified.

## Deliverables
- `src/engine/git/indexReader.ts`: `readIndex(fs): Promise<IndexSnapshot>` and pure `parseIndex(bytes: Uint8Array): IndexSnapshot`.
  ```ts
  interface IndexEntry {
    path: string; oid: Oid; mode: number; size: number;
    mtimeSec: number; mtimeNsec: number; ctimeSec: number; ctimeNsec: number;
    stage: 0 | 1 | 2 | 3;
    assumeValid: boolean; skipWorktree: boolean; intentToAdd: boolean;
  }
  interface IndexSnapshot {
    version: 2 | 3 | 4;
    entries: IndexEntry[];                       // sorted as on disk (path, stage)
    byPath: Record<string, IndexEntry>;          // stage-0 entries only
    conflicts: Record<string, IndexEntry[]>;     // path -> stage 1/2/3 entries
    extensions: string[];                        // e.g. ["TREE","REUC","UNTR","link","sdir"]
    hasSplitIndex: boolean; hasSparseIndex: boolean;
    checksumOk: boolean;
  }
  ```
- Extend `RepoInfo.capabilities` population hook (used by T3.5).

## Format details to implement
- Header: `"DIRC"`, u32 version, u32 entry count. Version ∉ {2,3,4} → `EngineError("INDEX_UNSUPPORTED")`.
- Entry (big-endian): ctime s/ns, mtime s/ns, dev, ino, mode, uid, gid, size (10 × u32), sha1[20], flags u16 (`assumeValid = bit15`, `extended = bit14`, `stage = bits 13–12`, `nameLen = low 12 bits`, 0xFFF means "≥ 4095, read to NUL").
- If version ≥ 3 and `extended`: u16 extended flags (`skipWorktree = bit14`, `intentToAdd = bit13`).
- Name: v2/v3 → NUL-terminated then pad so that entry length (from entry start, 62 or 64 + name + NUL) is a multiple of 8. v4 → varint (git "offset encoding": MSB-continued, each continuation adds 1 before shifting, see `git/varint.c`) = number of bytes to remove from the **previous** entry's path, then NUL-terminated suffix, no padding.
- Extensions after entries until 20 bytes before EOF: 4-byte signature + u32 length + payload. Record signatures; set `hasSplitIndex` if `"link"`, `hasSparseIndex` if `"sdir"`. Skip payloads.
- Trailer: SHA-1 of everything before it; compute with `crypto.subtle.digest("SHA-1")` (via T2.2 helper if landed; otherwise inline) and set `checksumOk`.
- `readIndex` retries once after 150 ms if `checksumOk === false` or `ENOENT` (git writes `index.lock` then renames). After the retry, return the snapshot with `checksumOk=false` and let the caller warn.
- Sparse index: entries with mode `0o40000` (directory entries) are kept and flagged; `byPath` includes them so the scanner can treat them as opaque.

## Tests
- Byte-level: construct v2, v3 (with extended flags), v4 (with prefix compression across ≥ 3 entries with shared prefixes) buffers in the test with a tiny builder; verify all fields.
- Fixtures: `basic`/`worktree` (v2) vs `git ls-files -s` (write an expectation `ls-files-s.json` in T0.3 if missing — add to the script); `index-v3`, `index-v4`; `conflict` (stages 1/2/3 grouped); a corrupted trailer buffer → `checksumOk=false`.

## Acceptance criteria
- [ ] All tests green; `perf-5k` index parses < 50 ms.
- [ ] No writes; `readIndex` uses only `readFile(".git/index")`.

## Amendments (review round 1)
- `IndexSnapshot` gains `indexMtimeMs: number` (the index file's `lastModified`, captured in `readIndex`) — needed for git's racy-clean rule in T2.4.
- Sparse-dir entries: strip the trailing `/` from `path` (path convention) and set `isSparseDir: true` on the entry; `byPath` keys never end in `/`.
- `entries.length > 200_000` → `IndexSnapshot.tooLarge = true` (still parsed; T2.4/T3.2 skip the worktree layer with `INDEX_TOO_LARGE`).
