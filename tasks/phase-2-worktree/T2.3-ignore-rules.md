# T2.3 — Ignore rules with directory pruning

**Phase:** 2 · **Size:** M · **Depends on:** T1.1 · **Blocks:** T2.4
**Plan refs:** §5.5 step 3, §1 finding 2

## Goal
Answer "is this path ignored?" with git semantics, and crucially "is this directory ignored?" so the walker never descends into `node_modules`.

## Deliverables
- `src/engine/git/ignoreRules.ts` using the `ignore` npm package:
  ```ts
  class IgnoreRules {
    static async load(fs: FsaFs): Promise<IgnoreRules>          // reads .git/info/exclude and root .gitignore
    async enterDir(dirPath: string): Promise<void>               // lazily reads <dir>/.gitignore when the walker enters it
    isDirIgnored(dirPath: string): boolean                       // tests "<dir>/" against the layered rules
    isFileIgnored(filePath: string): boolean
  }
  ```
- Layering: one `ignore()` instance per directory that has a `.gitignore`, patterns re-rooted to that directory (prefix non-anchored patterns correctly: a pattern without a slash matches at any depth below that dir; a pattern with a leading or middle slash is anchored to that dir). Evaluate deepest-first; last matching rule wins, negation honoured, but a file inside an ignored directory cannot be re-included (git rule).
- `.git/info/exclude` treated as root-level rules with lowest precedence; `core.excludesFile` inaccessible → not applied (documented; warning code `GLOBAL_EXCLUDES_UNAVAILABLE` emitted once if config sets it).

## Tests
`ignore` fixture parity with `check-ignore.json` for the probe list (must include: `build/x`, `a.log`, `src/keep.log` (not ignored), `secret.txt`, `node_modules/pkg/index.js`, `ignored-dir/tracked.txt` (ignored by rules, but tracked files are handled by the scanner, not here)).
Unit: anchored vs unanchored patterns, `**`, trailing-slash dir-only patterns, negation, comments/blank lines, escaped `#`.

## Acceptance criteria
- [ ] Parity test green.
- [ ] `isDirIgnored("node_modules")` true without touching anything inside it (spy on fs).

## Amendments (review round 1)
- Constructor takes the `FsaFs` **extended** API (`readdirWithKinds`, `openFile`) from T1.1 amendments, not the isomorphic-git subset.
- **Built-in defaults** (lowest precedence, documented, toggleable via `opts.builtinExcludes` default `true`): `.DS_Store`, `._*`, `Thumbs.db`, `desktop.ini`. Git on macOS applies `~/.config/git/ignore` when present and most Macs have `.DS_Store` ignored there; without this every Mac repo shows `.DS_Store` as untracked. Parity tests run with `builtinExcludes: false`.
- `invalidate()` method so T6.1 can drop cached `.gitignore` contents when `.gitignore`/`.git/info/exclude` change.
