# T2.4 — WorktreeScanner: staged / unstaged / untracked

**Phase:** 2 · **Size:** L · **Depends on:** T2.1, T2.2, T2.3, T1.3, T1.5 · **Blocks:** T3.2
**Plan refs:** §5.5 (whole section), §6.7 limits, §11 R1/R2

## Goal
Reproduce `git status --porcelain=v2 --untracked-files=all` from the index, HEAD tree and the working directory, without writing, without walking ignored directories, and cheaply on re-scan.

## Deliverables
- `src/engine/git/worktree.ts`:
  ```ts
  interface Change { oldOid: Oid | null; newOid: Oid | null; oldMode: number | null; newMode: number | null; }
  interface WorktreeStatus {
    staged: Record<string, Change>;        // index vs HEAD tree
    unstaged: Record<string, Change>;      // worktree vs index (newOid null = deleted; newOid may be lazily "pending" -> see below)
    untracked: string[];
    conflicts: string[];
    warnings: RepoWarning[];
    stats: { indexEntries: number; hashed: number; statOnly: number; walkedDirs: number; durationMs: number };
  }
  class WorktreeScanner {
    constructor(fs: FsaFs /* extended API: openFile, readdirWithKinds, getDirHandle (T1.1 amendments) */, db: ObjectDb, cfg: GitConfig, ignore: IgnoreRules, opts?: { maxUntracked?: number; concurrency?: number; hashUntrackedUpTo?: number })
    scan(index: IndexSnapshot, headTree: FlatTree | null, signal?: AbortSignal): Promise<WorktreeStatus>
    forgetStatCache(): void               // force re-hash (T6.4)
  }
  ```

## Algorithm (implement exactly; see Plan §5.5)
1. **Staged**: for every path in `index.byPath` ∪ `headTree`: compare oid+mode; produce added/modified/deleted. `intentToAdd` entries count as **not** staged (they show as unstaged-added in git). Unborn repo: `headTree = null` → everything in index is staged-added.
2. **Unstaged**, per stage-0 index entry, with a concurrency limiter (default 32):
   - `assumeValid` or `skipWorktree` → clean.
   - resolve file handle; `ENOENT` → deleted (`newOid: null`). Sparse-dir entries → skip.
   - `f = getFile()`; `mtimeMs = mtimeSec*1000 + floor(mtimeNsec/1e6)`; if `f.size === entry.size && f.lastModified === mtimeMs` → clean (**racy-git heuristic**, documented).
   - else: session cache `path → {size, lastModified, oid}`; hit → use oid; miss → read + `hashBlob` (stream if > 8 MB) → store.
   - `oid !== entry.oid` → modified with `newOid`. Mode: FSA has no mode; keep `newMode = entry.mode` (mode changes cannot be detected from the worktree; documented limitation, `chmod` shows only once staged).
   - `intentToAdd` entries: always hash → unstaged added.
3. **Untracked**: DFS from root with `IgnoreRules`; skip `.git`; skip any dir containing `.git` (embedded repo → warning `EMBEDDED_REPO`); `isDirIgnored` → prune; files not in `index.byPath` and not `isFileIgnored` → untracked. Stop at `maxUntracked` (5000) → warning `UNTRACKED_CAPPED`. Also prune descending into a directory when its path is a sparse-dir index entry.
4. **Conflicts**: `index.conflicts` keys.
5. CRLF: if `cfg.core.autocrlf` is `true`/`input` emit warning `AUTOCRLF` once (no normalisation in v1).
6. Honour `signal`: check between batches; throw `EngineError("CANCELLED")`.

## Tests (parity with `status-porcelain-v2.json`)
- `worktree` fixture: every listed case (staged mod, unstaged mod, both, staged new, untracked, untracked in new dir, deleted-unstaged, deleted-staged, mode change (expect: detected as **staged** only), reverted file (expect: unstaged shows modified relative to index but final oid = base — T3.2 eliminates it, not this task)).
- `ignore` fixture: `node_modules` never opened (spy), 200 files not in untracked; `src/keep.log` untracked; `secret.txt` not.
- `conflict`, `unborn`, `index-v3` (intent-to-add), `embedded`, `crlf` (warning emitted).
- Re-scan after touching a file's mtime without changing content: entry is hashed once, reported clean; stat cache hit on third scan (stats counters).
- Cancellation via `AbortSignal` rejects with `CANCELLED`.

## Amendments (review round 1) — these override the algorithm bullets above where they differ
1. **Refuse/skip conditions** (checked first): `index.hasSplitIndex` → throw `EngineError("SPLIT_INDEX")` (T3.2 catches and skips the layer with the warning); `index.tooLarge` → throw `INDEX_TOO_LARGE` likewise.
2. **Staged pass** iterates `stage-0 byPath ∪ headTree` **minus** `index.conflicts` keys and minus any path under a sparse-dir entry. Conflicted paths are reported only in `conflicts` (never as staged-deleted). Sparse-dir entries themselves are compared against `headTree` as opaque subtrees: skip (documented).
3. **Unstaged pass ordering and racy-clean rule** (replaces step 2's stat heuristic):
   - Modes `120000` (symlink: FSA returns the target file's bytes, not the link text) and `160000` (gitlink: a directory, `getFileHandle` would throw) → **always clean**, documented limitation; no I/O.
   - `f = openFile(path)` (`ENOENT` → deleted; `EISDIR` → treat as deleted-and-replaced-by-dir: report deleted, warn once `PATH_TYPE_CHANGED`).
   - **Cache first**: session cache `path → {size, lastModified, oid}`; hit with equal `size`+`lastModified` → use cached oid (this is what makes a force-refresh result stick across later polls).
   - **Racy-clean rule** (git's): if `f.lastModified >= index.indexMtimeMs` the stat data cannot be trusted → hash.
   - Else stat-clean check (`size` and `mtimeMs` equal) → clean; else hash. Store hash results in the cache.
   - `forgetStatCache()` (force refresh) clears the cache **and** sets a one-shot `hashAll` flag so the next scan hashes every entry regardless of stat, repopulating the cache.
4. **Untracked pass**: prune a directory when it contains a `.git` entry of **either kind** (file or dir) → `EMBEDDED_REPO`. Untracked files ≤ `hashUntrackedUpTo` (default 1 MB) are hashed during the scan and reported with `newOid` (needed for viewed keys and exact-rename detection); larger ones keep `newOid: null`.
5. Sparse subtrees are never walked.
Tests added: `conflict` (no staged-deleted for the conflicted path), `submodule` (no throw; gitlink clean), `symlink` (clean in unstaged), racy case (`touch -r .git/index file` then edit same size within the same ms → detected on the racy rule), force-refresh persistence across three scans, `index-v4` sparse-dir skip (add `git sparse-checkout` fixture variant if cheap; otherwise synthetic snapshot).
