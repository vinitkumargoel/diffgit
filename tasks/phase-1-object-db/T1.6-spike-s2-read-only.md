# T1.6 — Spike S2: read-only verification on real repos

**Phase:** 1 · **Size:** S · **Depends on:** T1.1–T1.4 · **Blocks:** Phase 2 sign-off
**Plan refs:** §11 S2, §1 findings 1–2, D16

## Goal
Prove, with a log of every fs call, that the Phase 1 stack performs zero writes and reads correctly on real repositories, including packed and multi-pack-index cases.

## Deliverables
- `scripts/spike-s2.ts` (run with `bun`): takes a directory path, wraps `nodeDirHandle` with a call-logging proxy, runs: layout check → config → refs → merge-base(default, HEAD) → flattenTree(both) → readBlob for 20 random entries. Prints timing per step and the count of calls per method.
- `docs/engine-notes.md` section "S2 results": table per repo (name, `.git` size, pack count, index entries, timings, any failure), plus every isomorphic-git limitation encountered and the chosen workaround.

## Repos to run (owner names three real repos; suggested)
- A small personal repo, a medium repo with `node_modules`, and one repo after `git gc` / `git multi-pack-index write` (create the MIDX on a copy to test the warning path).

## Acceptance criteria
- [ ] Zero calls to any write method in the log for all repos (assert in script, exit 1 otherwise).
- [ ] `git status` / `git fsck` output on each repo identical before and after (script captures both).
- [ ] Multi-pack-index repo: reads succeed or the failure is documented with a decision (block MIDX repos with a fatal error vs. still works).
- [ ] Any needed change to T1.1–T1.4 filed as follow-up tasks in CHANGELOG.

## Amendments (review round 1)
- **Zero-write proof on a real filesystem**: before the run, `touch marker`; after, `find .git -newer marker -type f` must print nothing (the memory-handle spy cannot prove this). Include in the script and in `docs/engine-notes.md`. Reused by T8.2.
- Also run the `sha256`, `alternates`, `partial` fixtures to confirm the refusals fire before any object read.
