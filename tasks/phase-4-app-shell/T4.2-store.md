# T4.2 — Zustand store

**Phase:** 4 · **Size:** S · **Depends on:** T4.1 · **Blocks:** T4.3, T5.x, T6.1
**Plan refs:** §6.3

## Goal
Single store shaped as in Plan §6.3, with actions that are thin wrappers over the worker client, and selectors the components use.

## Deliverables
- `src/ui/store.ts` with slices: `repo`, `diff`, `loading`, `warnings`, `prefs`, `viewed`, `filter`, `activeFileId`, `refresh`.
- Actions: `openRepo(handle)`, `closeRepo()`, `setSource(name)`, `setTarget(name)`, `swapBranches()`, `setIncludeWorktree(bool)`, `recompute(reason)`, `loadFileDiff(id)`, `toggleViewed(id)`, `setFilter(text)`, `setPref(key, value)`, `setActiveFile(id)`.
- Derived selectors (memoised): `visibleFiles` (filter applied: substring on path, or glob when it contains `*`), `totals`, `viewedCount`, `canIncludeWorktree` (source is checked-out branch), `treeModel` (path → nested nodes for the sidebar).
- Per-file diff cache: `fileDiffs: Record<id, { status: "idle"|"loading"|"ready"|"error"; data? }>` invalidated on recompute.
- Viewed key = `repoId + sourceRef + targetRef + fileId + (newOid ?? "wt:" + newSize + ":" + newMtime) + (oldOid ?? "-")`, persisted via T4.3. `fileId` is always included: untracked files may share `newOid = null` and must never share a key.

## Tests (vitest)
Reducer-level tests with the mock client: defaults set from `RepoInfo` (source = checked-out, target = default), swap, include-worktree guard flips to false when source changes to a non-HEAD branch, filter glob, viewed key invalidation when oid changes.

## Acceptance criteria
- [ ] Tests green; no component imports the worker client directly (grep guard in `bun run check`).

## Amendments (review round 1)
- Defaults come from `defaultDiffSource(refs)` and `canIncludeWorktree` from `isWorktreeSource` (both `src/engine/diffSource.ts`); `source` defaults to `headBranch ?? "HEAD"` so detached/unborn repos open.
- `DiffSource` carries `sourceRef`/`targetRef`; picker selections set both.
- Every response from the client is checked against `diff.generation`; stale ones are dropped (and `STALE` rejections ignored).
- `fileDiffs` cache is an LRU (max 200 entries, both whitespace variants counted) to stop long sessions from retaining every hunk model.
- Stats arrive via the worker's `onStats` sink (T3.5); the store only calls `prioritise(visibleIds)` when the sidebar viewport changes (no UI-side batching).
- Tests added: detached repo default source `"HEAD"`; viewed keys differ for two untracked files; LRU eviction.
