# T0.4 — Test harness: DirHandleLike, Node/Memory handles, Playwright shim

## Goal
Engine code is written against a small `DirHandleLike` interface so it can run in `bun test` (backed by Node fs), in the browser (real FSA handles), and in Playwright (in-memory handles).

## Deliverables
- `src/engine/fs/dirHandleLike.ts`:
  ```ts
  export interface FileLike { size: number; lastModified: number; arrayBuffer(): Promise<ArrayBuffer>; stream(): ReadableStream<Uint8Array>; }
  export interface FileHandleLike { kind: "file"; name: string; getFile(): Promise<FileLike>; }
  export interface DirHandleLike {
    kind: "directory"; name: string;
    getDirectoryHandle(name: string): Promise<DirHandleLike>;   // throws NotFoundError-like {name:"NotFoundError"}
    getFileHandle(name: string): Promise<FileHandleLike>;
    entries(): AsyncIterable<[string, DirHandleLike | FileHandleLike]>;
  }
  export type HandleLike = DirHandleLike | FileHandleLike;
  ```
  Real `FileSystemDirectoryHandle` satisfies this structurally; never use `instanceof FileSystemFileHandle` anywhere in the engine — check `.kind`.
- `src/engine/fs/nodeDirHandle.ts` (test-only, imports `node:fs/promises`): wraps a directory path. `getFile()` returns `{size, lastModified: mtimeMs, arrayBuffer, stream}`. Symlinks: `lstat` → treat as file whose content is the link target bytes? **No** — mirror Chrome: follow the symlink (`stat`), since FSA cannot see links. Document.
- `src/engine/fs/memoryDirHandle.ts` (used by E2E and some unit tests): in-memory tree built from `{ "path/to/file": Uint8Array | string }`, mutable (`write(path, bytes)`, `remove(path)`, `touch(path)`), with `snapshotFromDisk(dir)` helper in Node to load a fixture into memory and `toInitScript()` that serialises it for Playwright `addInitScript`.
- `e2e/fsaShim.ts`: **see amendment below — the shim must survive structured clone.**
- `playwright.config.ts`: Chromium only, `webServer` runs `vite preview`, base URL, trace on retry.
- `src/test/smoke.test.ts`: opens `fixtures/basic` via `nodeDirHandle`, lists `.git` entries, reads `HEAD`.

## Amendments (review round 1)
### Shim transport (replaces the original `fsaShim` bullet)
A plain object with methods throws `DataCloneError` at `postMessage` and cannot be stored in IndexedDB, and mutations on the main-thread copy would never reach the worker. Design:
- The shim's `showDirectoryPicker` resolves to a **cloneable marker** `{ __diffgoelMemoryHandle: true, snapshotId, name }` (a plain object; `kind: "directory"` added for UI type checks).
- `src/engine/fs/resolveHandle.ts` (engine side, used by `worker.ts` and `session.ts`): if the received value is a marker **and** `import.meta.env.MODE === "test"`/`VITE_E2E === "1"`, build a `MemoryDirHandle` from the snapshot fetched over a test-only `BroadcastChannel("diffgoel-e2e")` RPC (`getSnapshot`, `applyMutation`, `emitObserverRecords`); otherwise pass the real handle through. Production builds tree-shake this path (`if (import.meta.env.VITE_E2E !== "1")` guard around the import).
- Test mutations (`page.evaluate(() => window.__diffgoel.mutate([...]))`) are applied in the worker's memory fs via the channel, then the observer stub on the main thread emits records for the same paths.
- IndexedDB persistence (T4.3) stores the marker as-is (cloneable); `ensurePermission` treats markers as `granted`.
- `isSameEntry` on markers compares `snapshotId`.
### D16 lint guard
Add to `bun run check`: grep `src/` for `createWritable`, `removeEntry`, `.move(`, `create: true`, `"readwrite"`; any hit fails.
### Scope note
The shim exists only to support the three smoke specs in T7.1. Implement the minimum: marker, snapshot RPC, `mutate`, `emitObserverRecords`. No fixtures beyond `remote`, `worktree` and a no-git snapshot need `toInitScript()` support.
