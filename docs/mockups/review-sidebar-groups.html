01 · VS Code, reverse-engineered from extensions/git/src/repository.ts, scmViewPane.ts and the docs

VS Code shows one row per diff, not per file, and puts the layer in the group, never on the row.V

The Source Control view keeps four resource groups in a fixed order, hides the ones that are empty, and lets a file appear twice when it has two different diffs. The row itself carries only a letter and a colour; everything else is in the header or on hover.

  • view mode
    List is the default (scm.defaultViewMode); Tree compresses single-child folders (scm.compactFolders, default on). In list mode the directory is a dimmed description after the name.
  • sort
    List sorts by path (default), name, or status; tree is always path with folders first. The commands are titled “Sort Changes by Name / Path / Status”.
  • hover
    Inline actions are hidden until .monaco-list-row:hover or focus; scm.alwaysShowActions pins them. Working-tree rows get open-file, discard, stage; index rows get open-file, unstage; group headers get view-all, stage-all / unstage-all, discard-all.
  • badge
    The activity-bar count is merge + index + workingTree (untracked included in mixed mode, added separately in separate mode). Folders carry a dot in the strongest child colour, except for deletions.
  • not there
    No per-file +n −m, no viewed ticks, no “committed on this branch” layer. Those three are diffgit's job, and they are why a copy of VS Code would not be enough.

Worth taking

  • Layer lives in the group header, not the row. The row stays a letter, a name and numbers.
  • Fixed group order, empties hidden. Users learn where to look; nothing shows a “(0)”.
  • Count pill per group, dot per folder, strike-through for deletes. Three cheap signals.
  • Actions appear on hover so the resting row is quiet.

Does not transfer

  • One row per diff. diffgit renders one card per file (merge-base → worktree); a duplicate row would point at the same card twice.
  • Stage / discard / commit. diffgit never writes. The only verbs are “viewed” and “filter”.
  • Colour-coded filenames. Design §2.1: colour is never the only signal. We keep the letter square and add a word or a tooltip.
  • Untracked = green “U”. Relative to the base branch an untracked file is an addition; the square stays A and the group says untracked.
02 · diffgit today Sidebar.tsx · FileTree.tsx · FileRow.tsx · LayerChip.tsx

Today the layer is a word pinned to every row, and the row runs out of room first.C

The sidebar is GitHub's file tree with layer chips added to each row. That works for a handful of files at 300 px. It stops working when a file is in two layers, when the sidebar is narrow, and when the question is “what have I not staged yet?”.

  • chips
    A chip costs 50–70 px of a 300 px row; two chips cost 120. At 220 px the name is the first thing to go: groups.test.tsx becomes grou… while “untracked” stays whole.
  • grouping
    No grouping. To see what is staged you scan chips or type layer:staged. Committed and uncommitted work interleave in path order.
  • double marks
    Untracked says it twice (A square + “untracked” chip); both says it twice too (“staged” “unstaged”).
  • folders
    Folder rows carry nothing: no count, no stats, no viewed state. Collapsing one hides information instead of summarising it.
  • deletes
    A deleted file looks like a modified one except for the red square.
03 · Proposal Precision tokens only · every control below is live

Group by layer. Keep the tree inside each group. Say the layer once, in the header, and mark only the exceptions on the row.P

Five groups in a fixed order (Conflicts · Staged · Unstaged · Untracked · Committed on compare), each a sticky header with a dot, a word, a count, its +n −m and its viewed progress. A file appears once, in the least-committed layer it touches, and carries git's own two-column code (MM, M·, ·M, ??) only when the header alone would not tell the whole story.

P4States· four things the grouped sidebar has to survive

P4a · “Include uncommitted changes” off, or compare is not the checked-out branch. There is one layer, so there are no headers: the sidebar is exactly today's tree. The Layer | Path control disappears with the second row.

P4b · Mid-merge. Conflicts pin to the top in red with UU; the group header is the only red chrome on the page.

P4c · Filter active (components). Headers read 2 of 5; empty groups vanish; the header line says 7 of 19 files as it does today.

P4d · A group fully viewed. Staged shows ✓ 5/5 in green and the header drops to 55 % like its rows. Collapse it and the review shrinks to what is left.

P5Keyboard· nothing new to learn; two keys gain a meaning on headers
  • j k
    Next / previous file, across groups, skipping headers and folders (unchanged: fileRows already excludes non-file rows).
  • ↑ ↓
    Move focus through every row including headers (roving tabindex, unchanged).
  • ← →
    On a header: collapse / expand the group. On a folder: as today. On a file: ← jumps to its folder, or to its group header when the file is at depth 0.
  • v
    Toggle viewed on the active file (unchanged). On a focused header: mark the whole group viewed (same as the hover button).
  • a11y
    Headers are role=treeitem aria-level=1 aria-expanded with the group word and count in the accessible name; files inside are level 2+. The XY code has aria-label="Staged and unstaged"; the visual glyph is aria-hidden.
04 · Decisions

Nine calls. Each has a recommendation; say which ones you overrule.D

  1. D1
    Group order: Conflicts, Staged, Unstaged, Untracked, Committed on compare.

    VS Code's order (merge, index, working tree, untracked) with the branch's own commits appended last, because they are the bulk and the part a reviewer has usually seen. The alternative, most-volatile-first (Untracked at the top), reads as “newest first” but breaks the habit every VS Code user already has.

    recommend: VS Code order + Committed last
  2. D2
    Default to Layer grouping whenever there is more than one layer.

    Grouping switches on when Include uncommitted changes is on and at least one uncommitted file exists; otherwise the sidebar is today's plain tree and the second header row is not rendered. The choice persists as a pref (sidebarGroup: "layer" | "path") next to sidebarLayout.

    recommend: layer by default, path as the pref
  3. D3
    A file appears once, in the least-committed layer it touches.

    Staged-then-edited lands under Unstaged with the MM code; the card is one diff (merge-base → worktree) so a second row would only be a second link to it. Precedence: conflict → unstaged → staged → untracked → committed.

    recommend: once, in Unstaged, with MM
  4. D4
    Replace row chips with git's XY code.

    Two monospace characters, fixed 24 px, coloured per column (X green = index, Y yellow = worktree, ?? purple, UU red) with a full-word tooltip and aria-label. In Layer mode it appears only on multi-layer files; in Path mode on every uncommitted file. The words survive in the group headers, the StatsRow chips (§7.2 item 4) and the FileCard header, which keeps LayerChip as is.

    recommend: XY code · alternative: keep chips but truncate the chip before the name
  5. D5
    Hide empty groups. Never render “(0)”.

    Same as VS Code's hideWhenEmpty; with a filter active a group that loses all its files disappears too, and the header of a surviving group reads k of n.

    recommend: hide
  6. D6
    Header anatomy and hover actions.

    dot · word · count pill · +n −m · viewed k/n; on hover the progress gives way to mark all viewed and only this group. Headers are position: sticky inside the scrolling body so the layer stays visible while a long group scrolls.

    recommend: as drawn in P2
  7. D7
    Folder rows summarise only while collapsed.

    Count and +n −m appear on a collapsed folder and vanish when it opens (its children carry them). No dot: the group header already says the layer, and a dot without a word would be colour-only.

    recommend: collapsed-only summary
  8. D8
    Strike through deleted names; keep A for untracked.

    Strike-through is VS Code's and every terminal's convention for a delete, costs nothing, and survives a narrow column where the red square is the only other clue. Untracked stays an addition relative to the base; the group and the ?? code say the rest.

    recommend: both
  9. D9
    Two header rows: 36 px (count · Tree | Flat) and 30 px (Layer | Path · n uncommitted).

    Two segmented controls in one 36 px row do not fit at 220 px. The second row exists only when grouping is possible (D2), so the single-layer case costs nothing.

    recommend: second row, conditional
