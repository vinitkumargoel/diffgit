01 — Home

History lives where the facts table is.

The landing page stays verbatim. The right column of the hero is the one thing that changes: on a first visit it is the six-row facts table you approved; once a repository has been opened it becomes Recent, using the same hairline rows, the same 14 px type and the same 360 px width. History is also reachable from the nav on every scroll position, and o still opens the picker.

  • source
    IndexedDB diffgit-repos — id, name, handle, lastOpenedAt, lastSource, lastTarget. Max 20. Nothing new is stored.
  • row
    name (500) · base…compare in mono · opened 3 h ago · access state · × on hover.
  • single
    One repo gets a Continue card instead of a one-row list: it is the most common case and deserves the bigger target.

    Up to 6 rows visible. From 7 up a filter input appears and the list scrolls inside the column. "Clear all" in the footer.

    Opening from history calls requestPermission({mode:"read"}) inside the click; the row shows its own inline state (H4) rather than a toast.

02 — Loading

Four phases, real counts, and an exit at every one.

Same centred column as today, but the screen now says which repository and which pair it is opening, how long it has been at it, and what each phase found. The engine already reports done / total and a per-phase duration; the screen just stops hiding them. Anything that goes wrong is shown on the phase it happened in, with the completed phases still ticked, so the user learns how far the repo got before it failed.

  • phases
    Reading refs → Parsing index → Scanning working tree → Computing diff. Sub-steps (layout, config) fold into "Reading refs" as the mono caption.
  • counts
    Done phases keep their result ("412 refs", "8,120 entries"); the current one shows done / total and a bar when total is known, an indeterminate bar when it is not.
  • time
    Elapsed in the corner from 2 s; expected duration from the last open of the same repo (stored with the recent entry).
  • slow
    At 8 s a yellow callout names the likely reason (large packs, many untracked files) from the warnings received so far.
  • failure
    The phase gets a red ✕, the message + hint + actions appear under it. The full error screen (§4) is used only when there is no phase to attach to.

03 — Stats

The second row tells the truth about the numbers.

Row 2 of the top bar keeps its place and height. It gains a status breakdown (how many M / A / D / R / T), a layer breakdown (staged / unstaged / untracked), and an honest state for every moment the numbers are not final: streaming, partial, refreshing, filtered, failed. A number that is not yet true is never rendered as if it were.

  • ready
    11 files changed · +576 −131 · M 6 A 3 D 1 R 1 · staged 4 unstaged 6 untracked 1 · 3 / 11 viewed with bar.
  • streaming
    +/− shows a skeleton and "stats 42 / 118"; the totals are printed only once every file has stats. Rows fill in visible-first, as today.
  • partial
    Skipped files (too large, binary, stats read failed) are counted next to the totals with a link that scrolls to the banner or first such row.
  • refreshing
    Numbers dim to 55 % and a small spinner says "updating"; they never jump to 0 between computes.
  • filtered
    "8 of 118 match" replaces the file count; +/− are for the match, the total is in the tooltip.

04 — Errors

Every public code, one shape.

The error screen keeps the centred 560 px column and gains a fixed anatomy: a tinted icon tile, title + code + repo name, one sentence on what happened, a "What to do" box that quotes the exact command or folder when there is one, actions in a fixed order (primary · secondary · Forget on the right), and collapsible details with a copy button. All 19 public codes from src/engine/errors.ts are below, grouped by who can fix them. Toasts and file-level failures follow, then all 21 warning banners.

  • tile
    red: the repo is unusable here · yellow: access or environment, fixable now · blue: transient, retry · grey: informational, no action.
  • primary
    choose-folder → Choose another folder · retry → Retry · reopen-permission → Grant access. Always the ink button, always first.
  • forget
    Only when the repo came from history; ghost button, right-aligned, 5 s Undo.
  • details
    Raw engine message + code + build id, monospace, one-click copy for bug reports. Hidden until opened.
  • hint
    The engine's hint lands in the "What to do" box, never as a second grey paragraph.

05 — Browser gate

"Can't open local folders" becomes a page with a way forward.

Today the gate is three grey lines and a list of browser names. The redesign keeps the brand, says which browser it detected and why that one can't, offers the four browsers that can as real links, lets the user copy the address to a desktop, and, because the landing page's demo works in every browser, keeps the demo reachable so the visit is not wasted. Six causes produce six different pages; the layout is the same in all of them.

  • detect
    navigator.userAgentData?.brands first, then UA sniffing for Firefox / Safari / iOS / Android; window.isSecureContext; window.top !== window; Chromium version from brands.
  • headline
    Always "This browser can't open local folders." The red word is the one thing that differs: browser, phone, address, frame, version, policy.
  • right column
    Copy-link card (for phones and wrong browsers) or a "what to do" step list (for fixable causes), and the demo card, always.
  • privacy
    The read-only / no-upload / no-analytics line stays, as three icon facts, not a paragraph.
  • never
    No "download Chrome" pressure, no user-agent string on screen, no auto-redirects.
