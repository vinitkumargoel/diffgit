## T10.5 — Commit walker, commit-graph reader, lanes, ahead/behind, branch overview (2026-09-19)

- New `src/engine/git/commitGraph.ts` parses and checksum-verifies `.git/objects/info/commit-graph` (header, `OIDF` fanout, `OIDL` lookup, `CDAT` rows, `EDGE` octopus list), giving `oid → {tree, parents, commitTime, generation}` in O(log n) without inflating a commit object — the thing isomorphic-git has no support for at all (atlas tab 20). It verifies every commit in the `history` fixture against `readCommit`; a split-graph chain, a SHA-256 graph, an unknown version or a bad trailer all degrade to `graphAvailable: false` (the last two with a `COMMIT_GRAPH_STALE` warning), and an oid the graph does not list always falls back to an object read, so the graph is never trusted for existence.
- New `src/engine/git/walk.ts` (`walkCommits`, `placeCommit`, `reachableFrom`, `aheadBehind`), `commits.ts` (`commitDetails`, `commitStats`) and `branches.ts` (`branchOverview`, `branchCells`, `upstreamOf`); `EngineApi`/`RepoSession`/`WorkerClient` gained all seven methods, each single-in-flight, plus the `"history"` progress phase. `ObjectDb.readCommit` now returns the author/committer/`gpgsig` headers and `ObjectDb.readNote` reads `refs/notes/commits`.
- **Decisions:** `--date-order` is git's *topological* order with a date tie-break (revision.c sets `topo_order` for it), not a plain date queue — the all-same-date fixtures prove the difference — so the walk queues a commit only once every discovered commit naming it as a parent has been emitted (git's indegree), newest first, ties by the order they became eligible (`prio_queue`'s insertion counter). It stays streaming: the indegree is over what has been discovered rather than a full pre-walk, which agrees with git whenever dates do not increase towards the parents. `all` seeds from every ref, tag and stash sorted by ref name and then `HEAD`, which is how `git log --all` seeds its own walk. The cursor is a self-contained JSON blob (queue, indegree map, discovered oids, lane table), so a page survives a worker restart. `commitStats` runs the existing rename detection, so the fixture's `git mv` is one file with git's numbers instead of an add plus a delete. `aheadBehind` builds both reachability sets rather than pruning at the merge base, because a commit reachable from the base can also be reached on a path that never passes through it. Recorded in `docs/v2-contracts.md` under `<!-- T10.5 -->`.
- Lanes are first-fit (gitk / Git Graph), carried across pages in the cursor. `edges` describes the band **below** each node — `from` a lane at this row, `to` a lane at the next — so the SVG never needs a third row: `straight` for a pass-through or the first-parent continuation, `merge` for a line moving into a lane another commit already reserved for that parent, `fork` for a new lane opened by a second or later parent, and a lane a `merge` lands in still carries its own pass-through. A path-filtered page carries no lanes at all, because a lane reserved for a commit the filter skips would never close. `reflog()` now fills `ReflogEntry.reachable` from one batched walk, so T11.3's `unreachable` badge needs no second call.
- Tests: `walk.test.ts` replays `git log --date-order` (plain, `--first-parent`, `--all`) on `history`, `octopus`, `crisscross`, `detached` and `perf-5k` — paged seven at a time so the cursor is exercised on every fixture — plus `git log -- <path>` on two paths, the lane-continuity invariant, `git rev-list --left-right --count`, criss-cross and unrelated histories, and `markReachable` against `reflog-orphan/expected/orphan.txt`; `commitGraph.test.ts` checks all 63 commits against `readCommit` and every degradation path; `commits.test.ts` equals `git show --numstat --first-parent` for every commit of `history` and `octopus`; `branches.test.ts` equals `git for-each-ref %(upstream:short)`, `rev-list --left-right --count` and `git branch --merged`. `fixture-expectations.sh` gained `log-head-*`/`log-all-date-order`, `commit-numstat`, `branch-upstream` and `branch-merged` recordings.
- `bun run record` writes `walks` / `commits` / `commitStats` / `branches` / `aheadBehind` / `reachable` into `<fixture>.v2.json` and records `octopus`; the mock serves all seven methods and pages the recorded history itself, so T11.5/T11.7 can build the list, the CommitCard and the Branches table against real data. `scripts/perf.ts` measures the first page on `perf-5k` (8 ms, budget 100) and the full `--all` walk of `history` with and without the commit-graph (13 ms vs 25 ms, 1.9×), written up in `docs/perf.md`.

## T10.4 — Why hidden: rule attribution, hidden listing, index flags (2026-09-19)

- `IgnoreRules` gained `explain(path, isDir)` / `explainPath(path, kind)` → `{ source, line, pattern, negated }`, byte-equal to `git check-ignore -v` on both oracles (`fixtures/hidden/expected/check-ignore.txt` and the older `fixtures/ignore/expected/check-ignore.json`, negation and `info/exclude` included). `isIgnored` is untouched: attribution is a second, lazy index over the same rule text, one single-rule matcher per line, because the `ignore` package's `test()` hands back the rule only for a *positive* match and drops it for a negation — so a re-including `!keep.log` could never be named otherwise.
- New `src/engine/git/explain.ts` (`explainPath`) folds the ignore rule, `IndexEntry.skipWorktree` / `assumeValid` / `isSparseDir`, the 10 MB gate (`HUGE_FILE_BYTES`) and `linguist-generated` into one `PathExplanation`, with the copyable `git check-ignore -v` / `git update-index --no-skip-worktree` / `--no-assume-unchanged` command per reason. `WorktreeScanner.listHidden` is its own opt-in walk (`HIDDEN_LIMIT` 2,000, `HIDDEN_CAPPED`); the normal scan is unchanged, so nothing pays for a list nobody asked for.
- **Decisions:** `shown` is true only when the path has a row in the current diff *and* nothing hides it, so everything `listHidden` returns answers `shown: false`; a tracked path is never reported as `ignored` (git shows it, and so do we); an ignored directory is one row with the count of its direct children and is never descended (atlas tab 08 "Risks": `node_modules` is 100k rows); a path under an ignored directory reports the rule that excluded the *outermost* such directory, which is where git stops looking; `too-large` comes from the rows of the last diff, the same classification that gated them. Built-in excludes have no file, so their `source` is `(built-in excludes)` where git prints `::` — the one divergence, and `builtinExcludes: false` removes it. Recorded in `docs/v2-contracts.md` under `<!-- T10.4 -->`.
- `OpenOptions.builtinExcludes` now travels `WorkerClient.open` → `EngineApi.open` → `SessionOptions` → `IgnoreRules` (and is retained across a worker crash), closing the engine half of backlog **B10**; the checkbox is T11.4. `EngineApi`/`RepoSession`/`WorkerClient` gained `explainPath` and `listHidden`, both single-in-flight.
- Tests: `explain.test.ts` replays both check-ignore oracles line by line, checks `explain` against `isPathIgnored` on every probe, covers nearest-file/last-rule/`info/exclude`/built-in precedence and the excluded-ancestor rule on in-memory repositories, and drives the real `hidden` fixture through a session for all five reasons plus `clean`, the `builtinExcludes: false` flip that makes `.DS_Store` an ordinary untracked file, `dist` as one row with `count: 3`, and the 2,000-row cap. `workerClient.test.ts` covers the same through the mock and asserts `open()` forwards the preference.
